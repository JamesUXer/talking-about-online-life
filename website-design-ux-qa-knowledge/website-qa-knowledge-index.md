# Website Design & UX QA — Knowledge Index

This pack supports the **Website Design & UX QA GPT**. It is deliberately separate from any specialist digital-learning QA system.

## Files

1. **website-design-ux-qa-rubric.md**  
   Detailed scoring criteria, evidence expectations, release gates and interpretation.

2. **website-design-principles-reference.md**  
   Visual, interaction, responsive, trust and UX principles used to explain findings.

3. **website-qa-evidence-and-testing-guide.md**  
   Evidence classifications, confidence, accessibility checks, usability measures and rules preventing unsupported claims.

4. **website-qa-review-context-template.md**  
   Reusable intake structure for defining audience, tasks, scope, intended response, evidence and constraints.

5. **website-qa-implementation-handoff-template.md**  
   Developer-ready structure for approved findings, acceptance criteria, validation and the final Codex prompt.

## Retrieval guidance

- Use the rubric when scoring or prioritising findings.
- Use the principles reference to explain design consequences and recommendations.
- Use the evidence guide to classify certainty, select tests and prevent overclaiming.
- Use the context template when starting a new review or when scope is unclear.
- Use the handoff template only after findings are approved.

If sources conflict, follow the current GPT instructions for behaviour and workflow. Treat the knowledge files as reference material. For accessibility requirements, prefer the latest published WCAG 2.2 specification and state when a criterion or legal requirement needs current verification.

## Source foundation

The pack adapts reusable UX principles from the owner’s Career Accelerator notes and separates them from sector-specific criteria. Accessibility guidance is grounded in:

- [WCAG 2.2](https://www.w3.org/TR/WCAG22/)
- [W3C Evaluating Web Accessibility](https://www.w3.org/WAI/test-evaluate/)
- [W3C Involving Users in Evaluation](https://www.w3.org/WAI/test-evaluate/involving-users/)

Knowledge files provide reference material; the GPT’s permanent behaviour, priorities and output workflow remain in its Instructions field.
